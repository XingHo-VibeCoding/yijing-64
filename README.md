# 易经六十四卦

《易经》六十四卦的学习与整理项目。

## 项目目标

- 系统整理六十四卦的基本信息：卦名、卦符、卦序
- 逐卦记录卦象、卦辞、爻辞与个人理解
- 形成一份可检索、可长期维护的学习资料

## 技术栈

| 层 | 选型 | 备注 |
| --- | --- | --- |
| 前端 | React 19 + Vite 8 | 构建后为纯静态文件 |
| 卦数据 | 项目内 JSON，**打包进前端** | 不走网络、不查数据库（数据量小且不变） |
| 数据库 | CloudBase PostgreSQL | 只存用户数据：起卦记录 / 收藏 / 学习进度 |
| 权限 | PostgreSQL RLS 行级权限 | 数据库层强制「只能碰自己的行」 |
| 身份 | CloudBase 匿名登录 | 打开即用，不是登录页 |
| 后端接口 | **PostgREST 自动生成，本期不写云函数** | 建表即得 REST 接口 |
| 托管 | CloudBase 静态网站托管 | HTTPS + CDN |
| 成本 | **只用免费额度** | 不开按量计费、不设预置并发 |

> **两条架构主张**：① **卦数据不进数据库**（64 卦约 23KB、永不变更，放数据库只会多一次网络往返、多一份计费）；② **本期不写云函数**（少一层就少一个故障点和一份计费项）。
>
> 技术路线的完整比较、数据流图、错误处理与迁移注意事项见 [`docs/TECH_DESIGN.md`](docs/TECH_DESIGN.md)。

## 产品定位与边界（对齐 PRD v1.3）

### 主打功能

> **情绪价值 + 学习兴趣引导。**

不是知识库（全本原文到处都有），而是**让人愿意打开、并且愿意再打开**：

```
一键起卦（愿意打开）→ 读三层解读 → 每日第一卦自动存档（愿意再打开）→ 回看时进总表深读
```

### 五条边界

1. **起卦保留，但卦只释义、不断事** —— 起卦是主入口（P0）；解读只讲「这一卦在说什么」，不对未来下断言、不做决策建议、不出现「宜 / 不宜」
2. **吉凶不回避，方向固定** —— 吉卦戒骄躁，凶卦劝慰「**运随时变，成事在人**」。这是价值观引导，不是运势判定
3. **原文与解读必须分层可见** —— 一眼分清哪句是《周易》、哪句是本项目的理解
4. **不宣称任何感应或灵验** —— 起卦机制是随机数（**内部定论，不在界面做技术说明**）；界面用「**成事在人，莫问前程**」表达同一层意思。不做「诚心则灵」的暗示，不统计「准不准」
5. **不采集身份信息** —— 数据用匿名标识关联，不存手机号、邮箱、IP、设备指纹，不做行为埋点

> **起卦留着——它是入口；砍掉的是「拿卦替人做决定」的那部分。**
> 详见 [`docs/PRD.md`](docs/PRD.md) 第 4 节。

> **关于「用户进度」**：打开即用，没有注册和登录。系统在后台生成一个随机匿名标识来关联进度，
> 用户换浏览器或清缓存会丢失进度（这一点在界面上明确告知）。详见 PRD §6 F6 与 §7.3。

## 数据来源与校订

| 数据 | 来源 | 校验 |
| --- | --- | --- |
| 卦序 / 卦名 / 卦符 | 通行本（王弼本） | 卦符码点 U+4DC0–U+4DFF 连续 |
| 上下卦 / 六爻爻线 | 上下卦表推导 | 6 组自动校验 + **41 条外部全名比对**，0 矛盾 |
| 卦辞 / 象辞 | GitHub `sunls2/zhouyi`（通行本转录） | 与王弼本逐条核对；**修正源数据 2 处瑕疵** |
| 爻辞 / 小象 | 同上 | **384 条爻题阴阳与爻线交叉验证，0 不一致** |
| 吉 / 凶 / 平 | 按**卦辞整体处境**判定 | 每卦附判定依据，可追溯到卦辞；分布 39 吉 / 16 平 / 9 凶 |

- **白话解读一律留空**：第三方白话有版权与准确性风险，本项目不搬运、不自撰，宁愿显示「待补」。
- 繁简转换曾把「终日**乾乾**」误转为「干干」，现已逐字校订（同批数据中「干父之蛊」「噬干肉」「鸿渐于干」均为正确简化）。
