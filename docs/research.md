# 需求研究 · 易经六十四卦学习工具

> 日期：2026-09-18 ｜ 阶段：Day 3 需求研究 ｜ 下一步：Day 4 PRD
> 本文件只回答「要解决什么问题、别人怎么做、我们做什么不做什么」，不写技术方案。

---

## 一、一句话问题定义

**六十四卦的「卦名 — 卦象 — 卦序」对不上号，是初学者最大的门槛。现有工具两头都有、中间是空的：要么是面向占卜的「算命盘」，要么是面向研究者的「原文库」，唯独缺少「帮我记住」这一层。**

## 二、问题拆解

初学者学六十四卦，实际卡在三件事上：

1. **卦象认不出** —— 看到六条爻线（如 ䷔），说不出这是第几卦、叫什么名字
2. **卦序记不住** —— 知道乾、坤，但第 17 卦是什么？为什么是这个顺序？
3. **古文读不进** —— 卦辞爻辞是文言，不看白话读不懂；看了白话又变成「只看白话不看原文」

这三件事里，**第 1、2 件是纯记忆问题，第 3 件是理解问题**。记忆问题有明确解法（重复 + 即时反馈 + 进度可见），理解问题没有标准答案。

## 三、同类产品比较

### 3.1 爱周易 · 易经（iOS App，个人开发者）

**定位**：离线优先的《周易》研读工具，明确声明「不是占卜工具」。

| 维度 | 情况 |
| --- | --- |
| 文献库 | 六十四卦全文 + 十翼（系辞/说卦/序卦/杂卦），全离线 |
| 阅读体验 | 原文 / 白话 / 拼音 / 英译四层可自由开关；简体竖排可切 |
| 结构导航 | **关系卦导航：互卦、错卦、综卦、之卦** —— 把卦与卦的结构关联显性化 |
| 记忆闭环 | **六种测验模式**（卦名/卦象/卦序/卦辞填空/爻位/八卦）+ **掌握度标记** + **错题本** + 连续学习天数 |
| 起卦 | 有金钱卦、大衍筮法，但定位为「**文化仪式体验**」，界面内持续提示「不构成占卜、预测、运势判断或任何决策建议」 |
| 商业化 | 无账号、无广告、无追踪、无第三方分析 SDK |

**强在哪**：把「学习闭环」做透了——读 → 练 → 复习 → 进度可视，这是教育产品的正规打法，而不是内容堆砌。

### 3.2 易经宝典 · 周易六十四卦（iOS App）

**定位**：面向国学爱好者和初学者的图文速查 + 记忆测验工具。

| 维度 | 情况 |
| --- | --- |
| 内容 | 六十四卦卦辞、爻辞、彖传、象传 + 现代译文 |
| 图表 | 基础八卦、先天/后天八卦图、八宫六十四卦图、卦名次序歌 |
| 记忆 | 八卦测验 + 六十四卦测验，**看卦象选卦名、随机出题、显示正确率** |
| 视觉 | 国风视觉 + 楷体阅读；简体/繁体切换；交互音效 |

**强在哪**：**「看卦象选卦名」这个交互，直接命中了问题 1**。八宫图和卦名次序歌则针对问题 2。它的测验设计比阅读功能更值得学。

**弱在哪**：评价数据稀少（App Store 未积累足够评分），内容偏「陈列」而非「教学路径」。

### 3.3 易经思维（Android App，公司产品）

**定位**：移动学习 + 思维训练 + 社区，功能最全的一档。

| 维度 | 情况 |
| --- | --- |
| 学习 | 卦辞爻辞 + 白话 + 现代解读；**动态卦象推演**（模拟阴阳爻变）；难度分级 |
| 记录 | 每日一卦提醒、**卦象日记**、思维导图、云同步笔记与批注 |
| 起卦 | 硬币/时间/数字多种起卦，自动排盘，一键生成**本卦、互卦、变卦** |
| 其他 | AI 问答助理、朗读、社区共修打卡、离线藏经阁 |
| 体量 | 约 35 MB，备案号 京ICP备09030993号-6A，厂商为文化传播公司 |

**强在哪**：功能覆盖度最高，把「学、记、占、社区」四条线全做了。

**弱在哪**：**功能越全，初学者的决策成本越高**。首次进入要填兴趣问卷、选学习路径——对「我只想先把 64 卦认全」的人是负担。

### 3.4 参照对象：daooracle.life（网页学习站）

非 App，但它的**内容组织方式**值得抄：每一卦页面固定输出「卦象组成（上卦/下卦）→ 卦辞（中英）→ 象辞 → 现代释义」，并给每段内容标注 **来源层级（Source Tier）**，标明哪句是经典原文、登记 ID、出处链接。

**启发**：**「这段话是原文还是解读」必须让读者一眼可见**——这正是问题 3 的一部分解法。

### 3.5 资料源（不是竞品，是基础设施）

| 来源 | 说明 |
| --- | --- |
| **ctext.org 中国哲学书电子化计划** | 《周易》全文 + 十翼，王弼注本，**开放获取、免费**，支持全文检索与版本对照。是目前最权威的开放电子文本库 |
| 维基文库 | 周易全文，公有领域，带卦象图 |
| 汉典古籍 | 王弼本，卦名可跳转 |
| chinesenotes.com | 中文原文 + 英文翻译 |

**关键判断：原文文本本身是免费且开放的，没有任何版权壁垒，也不构成竞争壁垒。**

## 四、从研究里得到的三个结论

1. **竞争点不在「能不能起卦」，而在「能不能帮我记住」。**
   三款 App 全都有起卦功能，但没有一款把「卦象 ↔ 卦名 ↔ 卦序」的记忆做成主路径。而这恰好是初学者最痛的地方。

2. **「原文 / 白话 / 解读」必须分层可见。**
   爱周易用开关控制，daooracle.life 用来源标签。共同点是：不让读者混淆「古人说的」和「后人解释的」。这是信任感的来源。

3. **内容不是壁垒，学习闭环才是。**
   ctext.org 已经把最权威的原文免费开放了，任何人一天就能把数据搬过来。所以能拉开差距的只有：测验设计、进度可见、反馈即时。

## 五、哪个产品改变了我的想法

**是「爱周易 · 易经」。**

**我原本的想法**：做一个易经项目，免不了要碰「起卦/占卜」——这是这类产品最吸引眼球的卖点，不做就是自废武功。

**改变在哪**：它的做法完全相反——起卦功能**做了，但被降级为「文化仪式体验」**，并且在界面里持续声明「不构成占卜、预测、运势判断或任何决策建议」。真正的主线是**学习闭环**：六种测验 + 掌握度标记 + 错题本 + 连续天数。

**这让我换了一个视角**：这个产品的本质不是「算命工具」，而是**「一款让人把六十四卦背下来的学习工具」**。它的竞争对手不是各种排盘 App，而是 Anki 这类记忆工具。

**连带影响**：既然本质是记忆工具，那 Day 7 的 MVP 就应该先做「认得出卦象」这一个动作的闭环，其他全部延后。这条判断直接决定了下面的「本期不做」清单。

## 六、本期做 / 本期不做

### 本期做（Day 7 MVP 范围）

- 六十四卦列表页：序号、卦名、卦符、上卦/下卦
- 单卦详情页：卦象图（六条爻线按阴阳绘制）、卦辞原文
- **核心交互：看卦象选卦名**（从三选一做起，即时反馈）
- 数据本地化：`data/64卦总表.csv` 扩成含卦辞的完整数据文件
- 明确标注「原文 / 白话」层次，不混排

### 本期不做

| 不做的事 | 为什么不做的理由 |
| --- | --- |
| **起卦 / 占卜功能** | 定位风险大、争议高；研究显示头部产品都把它降级处理，不是必经之路 |
| **账号体系 / 登录** | MVP 阶段零用户，登录只会劝退；记忆进度先用浏览器本地存储 |
| **云端同步 / 社区** | 需要后端与运维，成本远超本期收益（Day 7 只做纯前端） |
| **AI 解卦问答** | 没有靠谱的评判标准，容易输出似是而非的内容，损害信任 |
| **十翼全文（系辞/说卦/序卦/杂卦）** | 范围太大；本期只做六十四卦本体，十翼留到后续版本 |
| **中英文对照 / 朗读 / 音效** | 属于体验增强，不是核心闭环，优先级最低 |
| **简体繁体切换** | 有真实需求但非早期瓶颈 |
| **App 上架（iOS/Android）** | 先做网页验证需求，App 的审核与维护成本不属于 MVP |
| **卦变推演（互卦/错卦/综卦/之卦）** | 属进阶内容，初学者连本卦都还没认全 |
