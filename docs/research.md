## 0. 目标用户

### 0.1 用户是谁

**对易经感兴趣、但不是为了算命迷信的人。**

具体到人：
- 读过或想读《周易》原文，但被古文和卦象符号挡在门外的人
- 学文史哲、做传统文化相关工作的学生和从业者
- 想理解「变化」「进退」这类思维方式，不想被运势叙事裹挟的人
- 被朋友安利过易经，搜出来的全是排盘软件，于是放弃的人

### 0.2 用户不是什么

- **不是求签问卦的人** —— 他们要理解文本，不要结论
- **不是易经研究者** —— 不需要历代注疏对照，不需要版本考据
- **不是要「学会算命」的人** —— 这一条决定了整个产品的边界

### 0.3 三个真实使用场景

| 场景 | 用户在做什么 | 现有工具的失败点 |
| --- | --- | --- |
| **通勤 15 分钟** | 想认识今天刷到的那一卦：䷔ 是什么？叫什么？大概讲什么？ | 排盘 App 直接给「凶」，查卦网站给一大段古文 |
| **周末坐下来读** | 想认真读一卦的完整内容：卦辞、六爻、象辞，并分清哪句是原文哪句是解释 | 找不到「分层清晰 + 有白话」的网页 |
| **睡前自测** | 看到卦象能不能说出卦名？第 17 卦是什么？ | **完全没有这类网页工具**（测验功能都锁在 App 里） |

### 0.4 由目标用户推出的两条产品边界（贯穿全文）

1. **不做预测结论。** 不输出「吉/凶/宜/忌/运势」，也不把解读包装成建议。
2. **原文和解读必须分层可见。** 让用户一眼分清「这是《周易》里的话」还是「这是后人的理解」。

> 六十四卦本身是先秦经典，属哲学与文献范畴；「用它预测吉凶」是后世的一种用法。本项目服务前者。

## 2. 主对比

### 2.1 易经闯关（iching.sjlyedu.com）★ 最直接的竞品 【已核实】

**定位**：网页端游戏化闯关，把六十四卦做成「闯关 + 图鉴 + 挑战」。

#### 页面结构
```
规模：18 个页面入口 ｜ 64 卦象 ｜ 6 个世界闯关章节 ｜ 4 个长期训练方向

路径一 · 从入门到通关（5 页）
  首页 index         主线学习、今日任务、每日复习入口
  闯关地图 map        6 个世界的关卡入口，显示解锁状态 / 已获星级 / 总进度
  闯关页 learn        课程 + 识图题 + 情境题 + 绘制题 + 结算反馈
  绘制练习 draw       手动画卦
  卦象图鉴 collection 按卡片浏览已解锁卦象

路径二 · 起卦与查阅（5 页）
  起卦查询 lookup     手动拨爻 / 随机起卦 / 数字直查
  每日一卦 daily      每天一卦 + 小测 + 心得记录
  故事馆 story        用故事和情境理解卦义
  AI 解卦 ai          结合处境获得卦义解读
  速查手册 print      64 卦速查索引（含打印样式 print.html）

路径三 · 复习与反馈（5 页）
  我的成就 profile    等级、错题、勋章与复习
  学习报告 stats      正确率、进度、热力图、薄弱项
  学习笔记 notes      记录自己的卦义理解
  闪卡记忆 quiz       复习卦名、卦象和记忆点
  速度挑战 battle     限时题测试熟练度和反应速度
另有两页：卦象配对 match（配对玩法强化卦名↔卦象）、卦象探索 explore（按结构和主题探索规律）
```

#### 主要数据
- **64 卦象**（核心数据就是卦符本身）
- 6 个世界的关卡定义、每关星级
- 4 个长期训练方向
- 用户数据：解锁状态、总进度、星级、等级、勋章、错题、正确率、热力图、薄弱项、笔记

#### 用户能完成的动作
- 按主线闯关推进，解锁图鉴
- **手动画卦**（通过自己画爻线来记「从下往上读」和阴阳结构）
- 玩闪卡记忆、速度挑战、卦象配对
- 起卦（手动拨爻 / 随机 / 数字直查）
- 看每日一卦 + 做小测 + 写反思
- 看学习报告（正确率 / 热力图 / 薄弱项）并回到弱项关卡补练
- 读故事馆的故事来理解卦义
- 用 AI 解卦结合自己的处境

#### 优点
- **把「记忆」做成了完整闭环**：闯关 → 星级 → 成就 → 错题 → 薄弱项 → 精准补练，这是我在所有研究对象里见到最完整的
- **三个路径入口分得很清楚**（学习 / 查阅 / 复习），新手不会被功能淹没
- **「绘制练习」是独创设计**：手动画卦这个动作，直接解决「卦象从下往上读」的认知难点，成本极低、效果极好
- 纯网页，不需要装 App，跨平台

#### 不足
- **有原文的骨架，没有原文的血肉**：全站围绕「64 卦象」做记忆，**没有看到卦辞、爻辞、白话译文的位置**。它教你认出 ䷔ 是噬嗑卦，但不告诉你噬嗑卦在讲什么
- **学习与占卜仍然混在一起**：「起卦查询」和「AI 解卦」放在同一层级，对「不想算命」的用户是干扰
- 18 个入口对目标用户仍是负担
- 没有任何来源标注，看不出内容依据什么版本

### 2.2 daooracle.life（网页，中英双语）【已核实】

**定位**：单页信息密度极高的《易经》学习与反思工具。

#### 页面结构
```
标题区        卦序 + 卦符 + 卦名 + 拼音 + 英文名（䷎ 谦 · Modesty）
Contents      页内锚点目录，11 个区块可跳转
卦象组成      上卦 / 下卦：卦符 + 卦名 + 自然意象（坤·地 / 艮·山）
卦辞          中文原文 + 英译 + 出处《周易》
              ★ 来源层级块：Tier=Classical Text / Registry ID=zhouyi-ctext / Scope / Reference
象辞          中文原文 + 英译
现代释义      白话解读 + ★ 解读边界块（Tier=Dao Oracle Interpretation，声明非经典原文、非专业建议）
应用场景      事业与决策 / 关系与合作 / 身心与节奏
              ★ 场景化占卜入口 8 个（姻缘、事业、财运、健康、搬迁、抉择、婚姻、考试）
爻辞          6 个爻：爻题 + 中英原文 + 小象
变卦关系      6 个爻变跳转卡（第 N 爻变 → 明夷 / 升 / 坤 / 小过 / 蹇 / 艮）
关联卦        互卦 / 错卦 / 综卦 / 交卦 / 序对卦，每个带卦符、卦名、英文名、算法说明
实用指导      长文中英对照
场景解读      感情姻缘 / 事业发展 / 财运 / 健康，四段中英双语 + 免责声明
FAQ           3 条常见问答（中英）
```

#### 主要数据
- 每卦：卦序、卦符、卦名、拼音、英文名
- 上下卦：卦符、卦名、自然意象
- 卦辞、象辞、爻辞（6 条）、小象 —— 全部中英双语
- 变卦关系（6 条）、关联卦（5 种）
- **来源元数据：Tier / Registry ID / Scope / Reference**
- 场景标签：事业、关系、身心、感情、财运、健康
- FAQ

#### 用户能完成的动作
- 用页内目录在 11 个区块间跳转
- 读中英对照原文，点 Reference 跳到 ctext.org 查出处
- 展开爻辞、点进任一爻变看新卦
- 点进互卦/错卦/综卦/交卦，观察卦与卦的结构关系
- 看某卦在事业/感情/财运/健康下的解读
- 进场景化占卜，走起卦流程
- 读 FAQ

#### 优点
- **「来源层级」标注是全部研究对象里最值得抄的设计**：明确区分经典原文与后人解读，还给 Registry ID 和出处链接——这正是「不算命」在界面上的落地
- **关联卦算法说明写得很清楚**（互卦取二至五爻、错卦阴阳互换、综卦上下颠倒、交卦上下卦互换），不让用户猜
- 单页一卦看透，信息架构清晰
- 中英双语，覆盖更广
- 有 FAQ，主动回答最困惑的问题

#### 不足
- **完全没有记忆/学习功能**：无测验、无进度、无收藏、无复习，读完就结束
- **「学习」和「占卜」两条线混在一起**（场景化占卜入口 + Start a Reading），与我的目标用户定位冲突
- 页面很长（11 区块），没有「作者认为的重点」
- 未确认是否覆盖完整 64 卦

- 听读（中英朗读、多卦连读、跟读高亮）

- 收藏、组卦单、生成卦象分享卡
- 标记「已掌握」看进度

#### 优点
- **学习闭环最完整**：读 → 练 → 复习 → 进度可视，是教育产品的正规打法
- **定位与我完全一致**：官方原话「坚持教育向，拒绝运势向」「明确不作占卜预测，也不提供决策建议」「若你正在寻找占卜结论或运势答案，这里不是合适的工具」
- **起卦做了但被降级**，且界面内持续免责——证明「不碰占卜」不等于自废武功
- 文本四层可开关，把「信息过载」的控制权交给用户
- 隐私克制（无账号、无追踪）、无障碍明确支持

#### 不足
- **iOS 17+ 独占**，Android 用户和「只想在电脑上查一下」的用户全被挡在门外
- **只有 1.0.0 首发版本**，长期维护能力未知
- 功能密度高，新用户进来不知道从哪开始
- 界面语言有繁简英三种，但原文是「公版 + 自制白话」，解读质量无法横向比较

### 2.4 周易学习网（zhouyi-iching.com）【文案】

**定位**：个人创建的免费学习站，自述「用现代语言与技术传承周易」。

#### 页面结构
```
关于本站      站长的创站宣言与目的
六十四卦体系   卦辞、爻辞、象传、白话译文、学习笔记
交互式学习工具 动态爻变 · 八卦关系 · 先天后天方位演示
八卦时辰表盘   十二时辰 + 二十四节气 + 后天八卦方位实时联动
              附六十甲子与天干地支速查
AI 辅助学习    帮助理解经典、连接现实情境、提供不同思考角度
中英双语      持续完善中
```

#### 主要数据
- 卦辞、爻辞、象传、白话译文
- 学习笔记（用户自建）
- 方位 / 时辰 / 节气数据、六十甲子、天干地支
- 动态爻变与八卦关系（可视化）

#### 用户能完成的动作
- 读六十四卦的原文与白话
- 看动态爻变、八卦关系、先天后天方位演示
- 用八卦时辰表盘查时辰/节气/方位的对应
- 写学习笔记
- 用 AI 辅助理解卦义

#### 优点
- **对我最有价值的一条：它把「难在哪」说清楚了**
  > 「《周易》真正困难的地方并不是内容本身，而是它特殊的表达方式——高度凝练的古文、抽象的卦象符号，以及复杂的卦序、爻变与空间关系，往往让许多人还没真正开始理解，就已经望而却步。」
  这段自我分析比我自己的问题拆解更准确，**直接可作为 PRD 的问题陈述**
- 定位与我的目标用户几乎一致（明确说「价值不仅仅在于占卜」）
- 核心内容长期免费开放
- 有原创的可视化模块（时辰表盘、动态爻变），不是纯文本堆砌
- 中英双语

#### 不足
- **没有测验、没有进度、没有复习**——只有「学习笔记」，不构成学习闭环
- AI 辅助的可靠性无从判断
- 内容「持续完善中」，实际覆盖度未知
- 是个人文化项目，产品化程度低，交互细节不可考

### 3.2 易经思维（Android App）【文案】

卦辞爻辞+白话+现代解读、动态卦象推演、难度分级、每日一卦、卦象日记、思维导图、云同步笔记、起卦工具（硬币/时间/数字，自动生成本卦/互卦/变卦）、AI 问答助理、朗读、社区共修打卡、离线藏经阁。约 35 MB，备案号 京ICP备09030993号-6A，厂商为文化传播公司。
→ **反面教材：功能越全，初学者决策成本越高**。首次进入要填兴趣问卷、选学习路径，对「我只想先把 64 卦认全」的人是负担。

### 3.3 易学网 eee-learning.com（网页，台湾）【文案】

占卜程式（易经牌初阶/中阶/进阶、焦氏易林）与学习工具并列：**八卦卦象学习卡（闪卡）**、**64 卦快闪记忆卡**、易经爻象闯关游戏、阴阳变易修练场。
→ 说明「闪卡记住卦象」这个做法在易学圈是共识，但**它的呈现停留在 20 年前的网页形态**。中英双语、可收藏难记卡片。

### 3.4 ctext.org 中国哲学书电子化计划【已核实（搜索确认）】

《周易》全文 + 十翼，王弼注本，开放获取、免费，支持全文检索与版本对照。
→ **不是竞品，是基础设施**。它说明：**原文文本免费且开放，没有版权壁垒，也就不构成竞争壁垒**。任何人一天就能把数据搬走。

## 5. 五条结论（附证据来源）

| # | 结论 | 证据 |
| --- | --- | --- |
| 1 | **「记忆」和「读原文」在这个品类里是分开的，没人合起来** | 易经闯关有完整记忆闭环但**只有卦象、没有卦辞爻辞**；daooracle.life 文本最全但**零记忆功能**；易经宝典两者都有但最浅。**这个交集是空的。** |
| 2 | **原文/解读分层标注，是「不算命」在界面上的落地方式** | daooracle.life 用 `Tier + Registry ID + Reference` 把「经典原文」和「后人解读」隔开；爱周易用开关实现四层文本。两者都证明这是可行且必要的 |
| 3 | **内容不是壁垒** | ctext.org 已把王弼本原文免费开放，一天可搬完。能拉开差距的只有测验设计、进度可见、反馈即时 |
| 4 | **功能越全，目标用户越容易跑** | 易经思维要填问卷选路径、18 个入口的易经闯关、爱周易的十翼+诵读+起卦——对比易经宝典（4 个页面）反而最好上手 |
| 5 | **用户的真实难点是「表达方式」，不是「内容量」** | 周易学习网的自我分析（凝练古文 + 抽象符号 + 复杂卦序/爻变/空间关系）比我自己的拆解更准确，应直接采用为问题陈述 |

## 6. 改变了我想法的产品

**是「爱周易 · 易经」。**

| | |
| --- | --- |
| **原本的想法** | 做一个易经项目，免不了要碰起卦占卜——这是这类产品最抓眼球的卖点，不做就是自废武功 |
| **改变在哪** | 它的做法完全相反：**起卦做了，但被降级为「文化仪式体验」**，界面内持续声明「不构成占卜、预测、运势判断或任何决策建议」。真正的主线是学习闭环：6 种测验 + 掌握度标记 + 错题本 + 连续学习天数。商店页更直接写「坚持教育向，拒绝运势向」 |
| **视角怎么换的** | 这个产品的本质不是「算命工具」，而是**一款让人把六十四卦背下来的学习工具**。它的竞品不是各种排盘 App，而是 Anki 这类记忆工具 |
| **直接后果** | 25 天 MVP 先做「认得出卦象」这一件事的闭环，起卦相关全部不做（见第 8 节） |

> 补充一个反向印证：**易经闯关** 把记忆闭环做成了 18 个页面、6 个世界、星级成就，却**完全没有原文内容**。这说明「记忆」这条路确实值钱，但也说明**只做记忆会缺一块**——用户记住 ䷔ 之后，下一步一定是「它到底在说什么」。**这一块就是我们的位置。**

## 7. 我能在 25 天内完成的最小版本

### 7.1 形态决策

**一个纯前端网页应用。** 不登录、不后端、不服务器。

理由：三个研究对象里，两个最好的产品（爱周易、易经宝典）都被 iOS 17+ 锁死，Android 和桌面用户全被排除；网页是唯一「谁都能打开」的形态，也最容易做出来给人看。

### 7.2 一句话定义

**一个能在网页上「认出卦象、读懂原文、记住卦序」的六十四卦学习页。**

### 7.3 四阶段

| 阶段 | 天 | 交付物 | 验收标准 | 主要风险 |
| --- | --- | --- | --- | --- |
| **一 · 能查** | 1–7 | 卦列表页（序号+卦名+卦符+上下卦）；单卦详情页（六爻卦象图、卦辞、象辞）；`data/64卦.json` | 64 卦全部能点开；**卦象图的爻线画对**（阴阳爻、从下往上读） | 卦象绘制容易画反上下顺序——这是本阶段唯一的硬技术点 |
| **二 · 能读** | 8–14 | 爻辞（6 条）+ 小象；**原文/白话分层切换**；每段带来源标注块（Tier + 出处） | 随便指一段，用户能说出「这是原文还是解读」 | 白话质量：必须有依据，不能自己编；宁可少译不可错译 |
| **三 · 能记** | 15–21 | **看卦象选卦名**（三选一，即时反馈，计分）；连对/连错提示；进度存浏览器本地 | 能做一轮 20 题，看到分数变化，刷新浏览器后进度还在 | 题目生成需避免重复与「送分题」（三个选项要够像） |
| **四 · 能找** | 22–25 | 搜索（卦名/序号）；按上下卦筛选；上一卦/下一卦快速翻页 | 输入「谦」能直接跳到第 15 卦 | 中文搜索匹配（简体/繁体/拼音首字母）范围要收敛，别做过头 |

### 7.4 数据来源

基于已有 `data/64卦总表.csv`（已含 64 条：序号、卦名、卦符、上下经）扩成含卦辞/象辞/爻辞的 `data/64卦.json`；**原文以 ctext.org 王弼本为准，每条标注出处**。

### 7.5 整体验收

随便挑一卦，能在 3 次点击内看到它的卦象、卦辞和对应的白话，且能分清哪句是原文；能做一轮测验并拿到分数。

## 8. 本期不做

| 不做的事 | 为什么不做的理由 | 什么条件下可以解禁 |
| --- | --- | --- |
| **起卦 / 占卜 / 运势判断** | 与目标用户直接冲突。爱周易的实践证明了不做它是可行的 | 不考虑 |
| **输出任何「吉/凶/宜/忌」结论** | 「不算命」是立身之本，一旦输出结论就变味 | 不考虑 |
| **AI 解卦问答** | 没有靠谱评判标准，容易输出似是而非的内容，直接损害信任 | 有可核验的内容依据（如绑定具体注疏）之后 |
| **账号体系 / 登录** | MVP 阶段零用户，登录只会劝退 | 需要跨设备同步时 |
| **云端同步 / 社区 / 打卡排行** | 需要后端与运维，成本远超本期收益 | 有真实用户要求跨设备时 |
| **十翼全文（系辞/说卦/序卦/杂卦）** | 范围太大；本期只做六十四卦本体 | 六十四卦本体做扎实之后 |
| **变卦与关联卦推演（互卦/错卦/综卦/交卦）** | 属进阶内容，用户连本卦都还没认全时价值低 | 测验完成率稳定之后 |
| **中英文对照 / 朗读 / 音效 / 分享卡** | 体验增强项，不是核心闭环 | 核心闭环验证之后 |
| **简体繁体切换** | 有真实需求但不是早期瓶颈 | 有繁体用户反馈时 |
| **八卦图表页（先天/后天八卦图、八宫图、卦名次序歌）** | 易经宝典已做得很好，重复造轮子不如把力气放在记忆闭环上 | 不优先 |
| **App 上架（iOS / Android）** | 先做网页验证需求；审核与维护成本不属于 MVP | 网页版有稳定使用后再谈 |
| **通勤/离线场景优化（PWA 离线）** | 需求真实但优先级低于核心闭环 | 阶段四完成且有富余时间 |

4. **易经闯关是否收费**：总览页未见价格信息，但页面中出现「预约心理咨询」链接，商业模式不明。
5. **《易经思维》的 AI 问答效果**：来源是第三方软件下载站文案，无官方或用户评价佐证。
6. **三款 App 的实际用户量与评分**：爱周易（1.0.0 首发）、易经宝典（评分数据不足）都无法判断真实使用规模；仅知易经宝典在付费榜「参考资料」类 **#115**。
7. **daooracle.life 是否完整覆盖 64 卦**，及其「现代释义」「场景解读」的生成方式（人工 or AI）。这点直接影响它作为「来源分层」范本的可信度。
8. **搜索结果中出现的《易学入门》《易经小课堂》《易经解读》《易学论坛》《易占》《易经智慧应用》等名称**，来自一篇低质量聚合投稿，**无法确认真实存在，本次未采用**。
