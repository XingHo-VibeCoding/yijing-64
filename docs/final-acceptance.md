| `DELETE /me/data` | **200** | `{"cleared":{"records":1,"favorites":0,"rounds":0}}` |
| 无 token 访问 | **401** | 「缺少会话：请带 Authorization 头，或用 `?uid=demo-yijing64-user-a` 读示例数据」 |

**两处「看起来像 Bug」但查证后确认符合契约**（不记为缺陷）：

1. 传 `date:"不是日期"` 仍返回 201 —— 契约 2.2 明写「`date` **由服务端取当天**，客户端传了也忽略（防篡改、防时区漂移）」，代码 `shanghaiToday()` 一致。
2. 传 `changingLines:[9]` 被静默过滤成 `[]` —— 契约 2.2 约定「去重、升序、**过滤非法值后入库**」，代码一致。

**但契约自身有一处矛盾（如实记录，不影响运行）**：同一节里「错误」栏写着「`422`（`changingLines` 含非 1–6 的整数）」，与紧邻的「约定」栏「过滤非法值后入库」**互相冲突**。实测行为跟的是「约定」（过滤），文档的「错误」栏是错的。→ 已列入待修文档项。

**证据**：`.workbuddy/day28-api.json`、`.workbuddy/day28-api2.json`（脚本 `day28-api.cjs` / `day28-api2.cjs`）。

## 三、结营复盘：28 天里最大的一个认知改变

**从「把功能做出来」变成「证明它是对的，而且知道自己还不知道什么」。**

28 天前我的默认动作是：写代码 → 跑起来 → 觉得没问题。28 天后我的默认动作是：写代码 → **先问「怎么证明它对」** → 跑 → 把判据本身也怀疑一遍。

这个改变是被真实打出来的，不是想出来的：

- Day 24 那个「清空后立即写入」的竞态，**界面显示成功、Console 零报错**——所有「看起来正常」的信号都是假的，只有写完回读才抓到。
- Day 25 做发布检查 Skill 时，Skill 入库后第一次当发布门就**自己命中自己**（检查器的源码也在扫描范围内）。
- 今天做验收，我自己的两个判据先失效了：**POST 计数说 0、云端明明有数据**；**「是否进结果页」被总表页文本误命中**。如果我不查证就写进验收表，这两条会变成「已验证」。

所以最大的收获不是「做出了一个易经应用」，而是这句：**证据必须独立于被测对象产生。** 页面显示的「已记录」不算，云端回读才算；代理日志里的请求数不算，数据库里的行才算；我自己写的判据不算，被判据误导过一次的记录才算。
